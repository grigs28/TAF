# bench — Vegas 自适应并发调试工作目录

本目录是 **Vegas 全程调试测试**的脚本与结果统一存放处（**测试脚本一律从这里部署到 16**）。
测试目的：用 TAF 同款流程（扫描→预分组→分组→tar|zstd 压缩，不写带）跑真实混合数据，
驱动 Vegas 状态机每 120 秒决策，**标定 79（群晖 NAS）磁盘压力 API 与压缩产出之间的
拐点规律**，为 Vegas 接入 TAF 生产（`GROUP_VEGAS_SIGNAL_SOURCE=nas_api`）提供阈值依据。

测试在 16（生产机）上运行：`/mnt/SSD/bench/`，产出文件如下。

## 脚本（入仓，部署到 16 运行）

| 脚本 | 作用 |
|------|------|
| `bench_vegas.py` | Vegas 全程测试：扫描→分组→压缩，状态机每 120s 决策（已跑完，135 组/1588GB） |
| `bench_ladder_small.py` | 小文件组（4000~5500 文件/组）阶梯并发 4→8，每档 2 轮×n 组 |
| `bench_vegas.md` | bench_vegas 的说明文档 |

## 大文件的再生成

`scan.json` / `groups.json` 不入仓，重跑即自动生成（脚本优先复用已存在的 scan.json，
想强制重扫删除它即可）：

```bash
# 16 上（需 root：/mnt/79-fs 挂载点权限 d---------，普通用户读不了）
cd /mnt/SSD/bench
nohup /opt/conda3/envs/taf/bin/python bench_vegas.py >> run.log 2>&1 < /dev/null &
```

数据源：`/mnt/79-fs`（大文件区，均值 ~9.5MB）+ `/mnt/79-yzbak`（小文件区，均值 ~1.6MB），
每源限扫 800GB，混合形态用于验证"固定并发不可行、必须自适应"。

## Vegas 状态机（测试版本）

- 信号：内部产出 P（本周期完成源字节 MB/s）为主判据；79 API 的 util/await 为辅助
  （到顶判定、快速保护）；每 120s 一个决策周期
- PROBING：产出稳/升 → +1 上探；产出降 >5% → -1 进冷却；产出持平且 util≥95% → 到顶 -1
- STABLE：产出掉 >20%（数据形态变化）→ 重新探测；每 8 周期主动 +1 重探
- 快速保护：util≥98% 且 await≥25ms → 立即 -1
- 范围：n ∈ [3,12]，起点 4

## 已知结论（阶梯测试，~1MB 均值文件）

| 并发 | 读取 MB/s | util% | 产出 MB/s |
|------|-----------|-------|-----------|
| 4 | 292 | 79 | 183 |
| 5 | 341 | 93 | **172（拐点）** |
| 6 | 273 | — | 127（-30% 坍塌） |

混合数据下 4 并发即可达 687MB/s / 11563 IOPS / util 95%（大文件区），
证明最优并发随数据形态漂移，需 Vegas 持续自适应。

## 全程测试结论（2026-10-24，135 组 / 1588GB，`vegas_decisions.csv`）

- **大文件区拐点 = 5**：4→5 P 609→695（+14%），5→6 P 695→618（-11% 坍塌）自动回退 ✓
- **小文件区**：5 并发 P 均值 ~273MB/s，79 read ~290MB/s
  （P 均值与真实读取吻合）
- **P 信号量化抖动**：小文件区单组 ~186s > 决策周期 120s → P 是完成组数×97.3MB/s
  的整数函数（97/195/292/389/487 阶梯跳变），±80% 摆动 → 已给 P 加
  EWMA（0.6/0.4）平滑，决策用平滑值、CSV 同时记 raw_P
- **状态机 bug（已修）**：`state='COOLDOWN'` 冷却扣完后不回 PROBING →
  死 hold（曾冻结 50 分钟）；修复：冷却扣到 0 置回 PROBING

## 小文件区阶梯实测结论（2026-10-24，`ladder_small_result.csv`）

全量组池 140 组（每组只用一次、洗牌防形态偏斜）、4~8→9 档、每档 2 轮×n 组、
偏差>15% 自动仲裁轮、8 未到顶自动 +1（上限 12）：

| n | 各轮 MB/s | 均值 | 判读 |
|---|----------|------|------|
| 6 | 270.8 / 280.0 | **275.4** | **顶峰** |
| 7 | 208.0 / 261.4 / 219.1 | 229.5 | 凹坑 |
| 8 | 245.9 / 290.4 / 257.7 | 264.7 | 反弹 |
| 9 | 268.8 / 245.7 | 257.2 | 回落→到顶确认 |

- 曲线非单调（6 峰→7 凹→8 弹→9 落），6~9 为**宽平台**（极差 7%）——小文件区
  对并发不敏感；对比大文件区窄拐点（5→6 即 -11% 坍塌）
- 79 全程 util 94~100% 打满，iops/read 仅微涨（3912→4561 / 224→260），
  await 始终 <11ms → 加并发不换真实吞吐，只改排队分布
- R2 系统性偏高（换档余波拖累 R1）→ 仲裁轮机制有效
- **阈值标定（已写入 bench_vegas.py）**：产出回退 -5%→**-12%**（EWMA 后）；
  STABLE 形态变化 0.8→0.85；快速保护 await 25→**15ms**；小文件区上限 9
- 方法学教训：上轮 7/8 档因组池循环重压被 page cache 污染（产出>79 实测 read
  +71%）——**阶梯测试每组只用一次**，组不足先扩池（全量扫描备池）
